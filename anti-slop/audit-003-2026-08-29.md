# Anti-Slop AFTER Audit 003 - 2026-08-29

Scope: requested improvements after total redesign: Inter typography, dashboard/table nav naming, dashboard status cleanup, dashboard splash behavior, HMI table layout, dynamic data rendering, mobile fit.

Design read: keep the compact mobile finance-app rhythm from the supplied reference, but apply it to TerraCure's agritech HMI. The HMI screen needs a true data table because the user's reference and task require comparing rules across four columns.

## Findings and Fixes

1. HIGH - Bottom-nav Dashboard tap could be blocked in local dev. Rule: R-03 / R-26 / R-35. Reason: Next dev overlay rendered as `NEXTJS-PORTAL` over the first bottom-nav item in the 375px test viewport. Fix: set `devIndicators: false` in `next.config.ts`, then verify navigation on production server.

2. HIGH - HMI content was cards, not the requested table. Rule: R-05 / R-20. Reason: cards made each rule easy to read alone, but they did not match the comparison task or the supplied table reference. Fix: rebuilt `HmiTable` as a real `<table>` with grouped row headers, dynamic row spans, and horizontal containment.

3. MEDIUM - Dashboard sensor cards mixed data rules into the component. Rule: R-23 / R-38. Reason: values came from sensor state, but the metric definitions were embedded in the dashboard component. Fix: moved metric definitions and severity rules into `data/sensor-metrics.ts`; the dashboard maps current sensor data through that source.

4. MEDIUM - Splash repeated on client navigation back to Dashboard. Rule: C-4 / R-26. Reason: local component state reset on route remount. Fix: added module-level runtime state so splash appears once per browser runtime and does not return during bottom-nav tab changes.
